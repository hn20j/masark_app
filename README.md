# مسارك (Masarak) — Flutter App

Masarak lets employees store a CV, browse published jobs, and save
application-assistance requests. Requests are not sent to employers and no AI
processing is performed unless a real backend integration is deployed.

This project implements the 5 wireframes you shared (onboarding, login,
sign up, home dashboard, CV upload) plus the additional screens a product
like this needs end-to-end.

### Why the extra pages
The wireframes covered onboarding and the CV upload prompt, and the app also
includes:
- A place to capture **target job / skills / target country** preferences.
- A **job feed** to browse and search published jobs.
- A **details + apply** screen that saves an application request without
  claiming it was sent to an employer.
- An **applications tracker** for saved requests and trusted status updates.
- A **profile/settings** screen for CV and account information.

## Architecture

- **State management:** `provider` (`lib/theme/app_state.dart`) — a single
  `AppState` holds the signed-in user and repository-backed app data.
- **Models:** `lib/models/models.dart` — `AppUser`, `Job`, `Application`, and
  notification records. Empty Firebase collections are shown as empty states.
- **Theme:** `lib/theme/app_theme.dart` — all colors, gradients, and shared
  button widgets (`PrimaryButton`, `PinkButton`, `OutlineButton`) live here
  so the app stays visually consistent with the wireframes (deep indigo
  backgrounds, violet primary actions, pink hero CTA).
- **RTL/Arabic:** the whole app is forced into `Locale('ar')` +
  `TextDirection.rtl` in `main.dart`, matching the wireframes.
- **Notifications:** the notification center reads Firestore notification
  records. Push delivery is not configured.

## Firebase services

The workspace root initializes Firebase before delegating to this package.
Firebase Auth handles email/password accounts and the profile/data repositories
use Firestore and Storage. Project-specific options are generated by running
`flutterfire configure` from the workspace root; repository rules and deployment
steps are documented in [the workspace root README](../README.md).

The callable `applyForMe` function records an internal queued request only.
External employer submissions, AI CV processing, interview scheduling, push
notifications, and App Check are not currently implemented.

## Getting started

```bash
# 1. Make sure Flutter is installed: https://docs.flutter.dev/get-started/install
flutter --version

# Run these commands from the workspace root (the parent directory).
flutter pub get

# Configure Firebase as described in ../README.md, then run:
flutter run
```

### Dependencies used (see `pubspec.yaml`)
- `google_fonts` — Cairo, an Arabic-friendly typeface
- `file_picker` — native file picker for CV upload
- `provider` — state management
- `flutter_localizations` — RTL/Arabic locale support
- Firebase Core, Authentication, Firestore, Storage, and Functions —
  configured from the workspace root
- `intl`, `flutter_svg`, `percent_indicator` — available for further polish
  (date formatting, icons, progress rings)
